## 2.1 How the dataset is organised
`data/raw/{train,student_test}/<trip_id>/<trip_id>.{track,nodes,arcs,route}`.

| File | Content | Parsed as |
|---|---|---|
| .track | lon, lat, t (s), no header | float (n x 3) |
| .nodes | lon, lat; row index = node id | float (N x 2) |
| .arcs | from_node, to_node; row index = arc_id | int (M x 2) |
| .route | ordered arc_id list (reference) | int (R) |

**Every trip has its own road network** (node and arc ids are local), so graphs, spatial indexes and features are built per trip. Trips lie on several continents (lon -100.4 to 137.2, lat -34.6 to 61.7).

| Partition | Trips | GPS fixes (total / mean / min / max) | Median nodes / arcs | Mean route arcs |

## 2.2 Preprocessing
1. **Coordinate checks:** lon is column 1, lat is column 2 (assert lon within +-180, lat within +-90; arc node ids within the node table).
2. **Sorting / cleaning:** drop non-finite rows and sort by timestamp. Found 0 NaN rows, 0 duplicate and 0 non-monotonic timestamps in both partitions, so nothing was removed.
3. **Projection:** each trip is projected to its own UTM zone (EPSG 326xx/327xx from the mean track lon/lat). Trips are spread over the world, so no single projected CRS is valid. A trip spans less than ~50 km, so one UTM zone keeps distance distortion small. Check: UTM track length vs haversine differs by at most 0.33 % (`utm_vs_haversine_err_pct`). Distances are never computed in degrees.
4. **Per-trip graph:** `networkx.DiGraph` with `arc_id` and metric `length` on each edge.
5. **Missing-value analysis:** no missing values in tracks. The real quality issues are time gaps and reference-route problems (2.3, `eda_quality.png`).

## 2.3 Patterns and data-quality findings
* **Sampling:** nominally 1 Hz; on average 94.3 % of steps are exactly 1 s. Train has 1,216 gaps > 5 s (69 gaps > 60 s); student_test has 44 (1 gap > 60 s). Extreme gaps: train trips 00000090 (153,064 s), 00000078 (52,810 s), 00000069 (2,658 s), 00000021 (2,161 s). The decoder must treat such gaps as segment breaks.
* **Road networks:** 89 of 90 trips have more than one weakly connected component (the largest holds at least 69.3 % of nodes), no isolated nodes. 92.2 % of arcs have a reverse arc (two-way roads stored as two arcs), so travel direction is the key signal for picking the correct candidate.
* **Reference route:** consecutive route arcs connect (to_node = next from_node) in 98.1-100 % of steps. 11 trips have breaks (14 breaks in total). The route is an ordered arc list **without timestamps**, i.e. not one label per GPS fix.
* **Reference vs track disagreement (label limitation):** for train trips 00000054 (88.9 % of fixes) and 00000033 (59.0 %) the track does not follow the supplied route (`anomaly_trip_*.png`); trips 00000002, 00000043, 00000066 have 7-12 %. Student_test is clean (0.07 % untrusted on average). We therefore do not treat the route as error-free ground truth (see 2.5).
* **Trajectory plots:** `eda_trajectories_network.png` (train trips 1, 2, 3, 4: GPS, network, reference route).
* **Folium maps:** `results/eda/folium_eda_student_test_00000007.html` (student_test) and `folium_eda_train_00000003.html` (train): raw GPS, network clipped to the trip bounding box, reference route, layer control, legend. *(For the PDF, take a screenshot of the HTML in a browser; the maps are generated by `run_eda.folium_map`.)*

## 2.4 Candidate generation
For every fix, a shapely STRtree over the trip's arc segments returns arcs within R metres, keeping the K nearest; if none lies within R the single nearest arc (up to 2 km) is used so every fix has at least one candidate. Result: 7.7 candidates per fix on train.

Candidate miss rate (reference arc absent from candidates, train, trusted fixes; `candidate_miss_sweep.csv`):

| R \ k | 1 | 3 | 5 | 10 | 15 | 20 |
|---|---|---|---|---|---|---|
| 25 m | 46.2 % | 6.38 % | 3.61 % | 2.58 % | 2.44 % | 2.38 % |
| 50-200 m | 45.5 % | 4.98 % | 1.97 % | 0.71 % | 0.49 % | 0.28 % |

Caveat: a trusted fix is by definition within 50 m of its reference arc, so the miss rate cannot change for R >= 50 m. **Choice: R = 100 m, K = 10** (R = 100 m is a safety margin for noisier unseen trips; k = 10 gives 0.71 % miss while keeping the HMM state space small). A nearest-arc-only (k = 1) baseline misses 45.5 %, because the nearest arc is often the opposite-direction twin or a parallel street.

## 2.5 Labels (reference arc per fix)
Monotone alignment of fixes to the ordered route by dynamic programming: minimise the sum of capped fix-to-arc distances subject to a non-decreasing route position, `dp_i[j] = c_i[j] + min_{k<=j} dp_{i-1}[k]` (`src/data/labels.py`). Direction is correct automatically because the two directions of a road are different arcs and the route lists the one travelled. A candidate is positive (`label = 1`) if it equals the aligned reference arc. Fixes whose aligned arc is farther than 50 m are flagged `trusted = False`; they are excluded from training and reported separately. Overall 93.0 % of train fixes (99.9 % of student_test) are trusted. Positive rate among candidates: 11.5 % (train), 12.1 % (student_test), i.e. about one positive per 8-9 candidates, which is imbalanced.

## 2.6 Features (`src/data/features.py`; label-free, so it runs on unseen trips in the API)
| Group | Features | Why |
|---|---|---|
| Closeness | d, rank, d_minus_min, d_ratio | perpendicular distance, absolute and relative to the other candidates |
| Heading / speed | cos_w1, cos_w3, speed_w1, speed_w3 | cosine of motion vector vs arc direction separates the two directions of a road; set to 0 below 3 m of movement because heading is noise when stationary |
| Position | frac, arc_len | projection position along the arc; short arcs at junctions are ambiguous |
| Temporal context | d_k-3..d_k3, d_ctx_mean/max/n30 | distance of the 3 previous/next fixes to the same arc: a true arc stays close, a parallel road drifts |
| Progress | adv_-1, adv_1 (+ ratios) | movement along the arc between consecutive fixes vs the actual step |
| Topology | out_deg_head, in_deg_tail, has_reverse, n_cand | junction vs mid-block, two-way vs one-way |
| Sampling | dt_prev, dt_next | local sampling interval |

No learned preprocessing is fitted here, so there is nothing to leak. Output tables: `data/processed/{train,student_test}_candidates.parquet` (1,615,030 and 157,872 rows; plus `sample_candidates.parquet` with 5 train trips).

## 2.7 Assumptions and decisions
* The route is reference information, not verified truth; label alignment is an approximation (distance threshold 50 m).
* Untrusted fixes are excluded from training and accuracy is reported on trusted fixes and on all fixes.
* Candidate radius 100 m, K = 10.
* Time gaps > 60 s are expected to break HMM transitions (decoder owner, section 5).
