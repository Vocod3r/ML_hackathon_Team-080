All numbers come from `python -m src.models.train_all` (outputs in `results/models/`). The table is generated by `python -m src.evaluation.report_table` and the plots by `python -m src.evaluation.plots`, so nothing below is typed by hand.

**Setup common to every model**
* **Task:** one row per (GPS fix, candidate arc), from AM320's candidate table (R = 100 m, K = 10). Binary target `label` = "this candidate is the reference arc". 29 label-free features (`data/processed/feature_cols.csv`).
* **Data:** 80 training trips (1,502,391 trusted candidate rows used for fitting), 10 student-testing trips for comparison. Untrusted fixes (aligned reference arc farther than 50 m, see 2.5) are **excluded from fitting but included in every score**, so the scores are not flattered.
* **Validation:** 5-fold `GroupKFold` by `trip_id`. All fixes of a trip are in the same fold, because fixes 1 s apart are almost identical and splitting a trip across folds would leak information.
* **Metrics** (`src/evaluation/metrics.py`):
  * **Top-1 accuracy:** per GPS fix, the highest-probability candidate is the prediction. A fix whose reference arc is not among its candidates counts as wrong.
  * **Macro F1:** per candidate row at threshold 0.5, averaging the F1 of both classes equally because only about 1 in 8.7 rows is positive.
  * **Log loss:** quality of the probabilities.
  * **Route continuity:** share of consecutive predicted arc changes (after collapsing repeats) where the end node of one arc is the start node of the next.
* **Reproducibility:** `random_state = 42` everywhere; Python 3.11, scikit-learn 1.9.1 (`results/models/environment.json`). Slow models were trained on a fixed random subsample (`max_train_rows` in `configs/models.yaml`).

## 3.2 Per-model analysis

Numbers quoted as "CV" are from 5-fold GroupKFold on the 80 training trips. "Test" is the student-testing partition. "Gap" = mean training-fold F1 minus mean validation-fold F1.

### 3.2.1 Logistic Regression (Linear)
**1. Why suitable:** the simplest probabilistic classifier. It tests whether a weighted sum of the features (distance, heading agreement, rank, ...) is enough to separate the true arc from its neighbours, and it gives a baseline every other model must beat.
**2. Strengths / limitations:** fast (7.5 s on 1.5 M rows, 0.0013 ms per fix) and interpretable. However, it can only draw a linear boundary, while the real rule is conditional (e.g. "close **and** heading agrees, unless the twin arc is equally close"). With `class_weight=balanced` it over-predicts the positive class: test recall of the true arc is 0.949 but 8.2 % of wrong arcs are also called positive, so precision drops to 0.803.
**5. Hyperparameters:** C = 1.0 (L2 regularisation strength), class_weight = balanced, max_iter = 2000, features standardised.
**6. Objective:** weighted binary cross-entropy (log loss) with an L2 penalty, solved with L-BFGS.
**7–8. Test results:** Top-1 0.8677, Macro F1 0.8499, log loss 0.1730, route continuity 0.7505.
Notably, its Top-1 accuracy is within 3 points of the best model while its F1 is much lower. Top-1 only needs the true arc to be *ranked first* within a fix, whereas F1 depends on the 0.5 threshold, which the class weighting shifts.
**9. Over/underfitting:** **underfitting**. Training F1 0.854 vs CV F1 0.830 is a small gap, but both are far below the non-linear models (0.91–0.93). It also has the largest fold-to-fold spread (± 0.044), so its limited capacity hurts more on some trips than others.

### 3.2.2 Gaussian Naive Bayes (Probabilistic)
**1. Why suitable:** a very cheap generative baseline that models each feature's distribution per class. It was included to test whether the features carry enough independent evidence on their own.
**2. Strengths / limitations:** trains in 0.4 s. However, its core assumption, that features are independent given the class, is badly violated: `d`, `rank`, `d_minus_min` and `d_ratio` all describe distance, and `cos_w1` and `cos_w3` both describe heading. The model counts the same evidence several times and becomes overconfident.
**5. Hyperparameters:** var_smoothing = 1e-9 (no other tunable parameters).
**6. Objective:** maximum-likelihood estimates of per-class Gaussian means and variances. There is no iterative loss.
**7–8. Test results:** Top-1 0.8337, Macro F1 0.7657, **log loss 2.0935** (about 30× worse than LightGBM), route continuity 0.7192. It calls 15.8 % of wrong arcs positive.
**9. Over/underfitting:** **underfitting.** Training F1 0.770 is close to CV F1 0.759 (gap 0.012), and both are the lowest of all models. The log loss shows that its probabilities are unusable for the HMM.

### 3.2.3 K-Nearest Neighbours (Instance-based)
**1. Why suitable:** the idea that "a candidate that looks like known true arcs is probably true" fits this problem: similar distance/heading/speed patterns recur across trips. It makes no assumption about the shape of the boundary.
**2. Strengths / limitations:** no training phase (0.07 s, it only stores rows) and a flexible boundary. However, prediction is slow (0.594 ms per fix, about 24× slower than LightGBM) because each query is compared with 200,000 stored rows. It also depends heavily on feature scaling.
**5. Hyperparameters:** n_neighbors = 25, weights = distance, features standardised, 200,000 training rows (memory and speed limit).
**6. Objective:** none. It is non-parametric: probability = distance-weighted share of positive neighbours.
**7–8. Test results:** Top-1 0.8729, Macro F1 0.9183, log loss 0.1552, route continuity 0.7383.
**9. Over/underfitting:** **overfits** in the sense of memorising. Training F1 is 1.000 vs CV F1 0.911, the largest gap of all models (0.089). Part of this is by construction: with distance weighting, each training row is its own nearest neighbour at distance 0. Its log loss (0.200 CV) is also poor, because averaging over 25 neighbours gives coarse probabilities.

### 3.2.4 Random Forest (Ensemble, bagging)
**1. Why suitable:** trees naturally learn conditional rules such as "if the distance difference to the best candidate is small, use heading", which is exactly how a human picks between twin arcs. Averaging 300 trees trained on bootstrap samples makes it robust to noisy labels.
**2. Strengths / limitations:** second-best CV F1 and the highest true-arc recall of the strong models (0.915), and it needs no scaling. However, deep trees on 1.5 M rows are slow, so it was trained on 400,000 rows (41.6 s). Its probabilities (vote shares) are less well calibrated than boosting: CV log loss 0.093 vs 0.075.
**5. Hyperparameters:** n_estimators = 300, min_samples_leaf = 5, max_features = sqrt, class_weight = balanced_subsample, 400,000 training rows.
**6. Objective:** each tree greedily minimises Gini impurity at every split. The forest averages the trees' class probabilities.
**7–8. Test results:** Top-1 0.8836, Macro F1 0.9303, log loss 0.0804, route continuity 0.7389.
**9. Over/underfitting:** **mild overfitting.** Training F1 0.971 vs CV F1 0.928 (gap 0.043). The fold spread (± 0.023) is as low as LightGBM's, so it generalises consistently across trips.

### 3.2.5 LightGBM (Gradient boosting), **selected**
**1. Why suitable:** like the forest it learns conditional, non-linear rules on mixed-scale features without scaling. Because each new tree corrects the remaining errors of the previous ones, it can model the fine distinctions between twin and parallel arcs. It is also fast enough to train on all 1.5 M rows.
**2. Strengths / limitations:** best on every metric (see table), trains in 16.7 s on the full data, 0.025 ms per fix. However, it has more hyperparameters, and boosting can overfit if run for too many rounds (see 9).
**5. Hyperparameters:** n_estimators = 500, learning_rate = 0.05, num_leaves = 63, subsample = 0.8 (bagging_freq 1), colsample_bytree = 0.8, no class weighting.
**6. Objective:** binary log loss. Each round fits a tree to the gradient of the loss (gradient boosting).
**7–8. Test results:** Top-1 **0.8991**, Macro F1 **0.9396**, log loss **0.0652**, route continuity **0.7695**. It has the lowest false-positive rate of all models: 1.3 % of wrong arcs are called positive.
**9. Over/underfitting:** **slight overfitting, controlled.** Training F1 0.968 vs CV F1 0.932 (gap 0.036). The boosting history (`07_history_lightgbm.png`) shows student-test log loss is lowest at round 251 (0.0645) and then flat (0.0652 at round 500), while training loss keeps falling to 0.039. Rounds after about 250 add almost nothing. This guided the search range for Bayesian optimisation (Section 4).

### 3.2.6 RBF Support Vector Machine (Kernel)
**1. Why suitable:** a maximum-margin classifier with an RBF kernel can draw smooth curved boundaries in feature space. It is a different inductive bias from trees, worth testing.
**2. Strengths / limitations:** competitive CV F1 (0.913) from only 30,000 rows. However, exact kernel SVM training scales roughly quadratically with the number of rows, and prediction scales with (support vectors × rows): 1.62 ms per fix, the slowest model, 65× slower than LightGBM. It also outputs margins rather than probabilities, so a sigmoid (Platt) calibration step is needed. This cost is why it was trained on a 30,000-row subsample (about 85 s per CV fold). It is acceptable for a comparison model, but the SVM would be too slow as the live API model.
**5. Hyperparameters:** C = 1.0, gamma = scale, class_weight = balanced, 30,000 training rows, features standardised, sigmoid calibration (3-fold).
**6. Objective:** hinge loss with L2 regularisation (maximum margin), then a sigmoid fitted by log loss for calibration.
**7–8. Test results:** Top-1 0.8714, Macro F1 0.9195, log loss 0.0930, route continuity 0.7527.
**9. Over/underfitting:** **slight overfitting.** Training F1 0.937 vs CV F1 0.913 (gap 0.024). Its main limitation is the 30,000-row cap: it sees 2 % of the data the boosting model uses.

### 3.2.7 Multi-Layer Perceptron (Neural network)
**1. Why suitable:** a small neural network can learn feature interactions (e.g. distance relative to heading agreement) directly from data, and it outputs smooth probabilities.
**2. Strengths / limitations:** third-best CV F1 and second-best test log loss (0.0751), with very fast inference (0.0014 ms per fix). However, it has the longest training (100 s) and the largest fold spread among the strong models (± 0.026), so it is sensitive to which trips it sees.
**5. Hyperparameters:** hidden layers (64, 32) with ReLU, alpha = 1e-4 (L2), learning_rate_init = 1e-3 (Adam), max_iter = 200, early_stopping = True (10 % internal validation, patience 10), features standardised.
**6. Objective:** binary cross-entropy (log loss) + L2 penalty, optimised with Adam.
**7–8. Test results:** Top-1 0.8930, Macro F1 0.9332, log loss 0.0751, route continuity 0.7654.
**9. Over/underfitting:** **slight overfitting, stopped early.** Training F1 0.952 vs CV F1 0.922 (gap 0.030). Early stopping ended training after **40 epochs** (of a possible 200). The training loss was still falling (0.055) but the internal validation score had stopped improving (`07_history_mlp.png`).

## 3.4 Model selection
Rule (`select_model` in `src/models/train_all.py`; output `results/models/model_selection.csv`, `selected_model.csv`), using **training-trip cross-validation only**. The student-test partition is reported but never used to choose:
1. **Primary metric:** mean CV Macro F1. Best: LightGBM, 0.9317 ± 0.0235.
2. **Shortlist:** every model within one fold-std of the best (≥ 0.9082), because smaller differences are within fold-to-fold noise. Shortlist: LightGBM, Random Forest, MLP, SVM, KNN.
3. **Tie-break:** lowest CV log loss, because the HMM decoder multiplies these probabilities, so calibration matters more than a fraction of a point of F1. LightGBM 0.0748 < MLP 0.0904 < RF 0.0931 < SVM 0.0987 < KNN 0.1996.
4. **Remaining tie:** fastest inference (not needed).

**Selected: LightGBM.** The held-out student-test results agree independently: LightGBM is best on Top-1, Macro F1, log loss and route continuity. At 0.025 ms per fix it is fast enough for the live API.

## 3.5 Findings across all models
* **One CV fold is hard for every model** (Top-1 0.50–0.53 vs 0.78–0.95 for the other folds, `runs/*_folds.csv`). The cause is the data, not the models: fold 1 contains train trip **00000054** (19,313 fixes, 41 % of that fold), whose GPS track does not follow its reference route (only 11 % of its fixes are trusted, Section 2.3). LightGBM's out-of-fold Top-1 on that trip is 0.08; without trips 00000054 and 00000033, fold 1 scores 0.85, in line with the others. All seven models fail together, which confirms it is a label problem.
* **Untrusted labels explain the gap between CV and test:** LightGBM's pooled out-of-fold Top-1 is 0.796 on all training fixes but **0.892 on trusted fixes**, which matches its student-test Top-1 (0.899, where 99.9 % of fixes are trusted).
* **Candidate generation is not the bottleneck:** the reference arc is missing from the candidates for only 0.21 % of student-test fixes, so the Top-1 ceiling is about 99.8 %.
* **Top-1 vs F1:** class weighting (LogReg, RF, NB, SVM) raises true-arc recall but also false positives at the 0.5 threshold. Top-1 is unaffected because it only depends on the ranking within a fix.
* **Independent per-fix predictions are not drivable routes:** route continuity is only 0.72–0.77 for every model, i.e. about a quarter of arc changes jump between unconnected arcs. This motivates the HMM / Viterbi decoder in Section 5, which enforces road-network connectivity between consecutive fixes.
